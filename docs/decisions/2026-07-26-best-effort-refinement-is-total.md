# Best-effort terminal refinement is total

`RefinementMode::BestEffort` currently fails. `D8RasterRefinementStrategy::refine_terminal` maps a failed `select_d8_raster_for_terminal` to `TerminalRefinementError::D8Selection` and then to `EngineError` with no mode check, so the mode named "best effort" aborts the whole delineation whenever declaration selection fails. Only two conditions degrade today: `NoD8AuxDeclared`, checked ahead of the strategy in `Engine::refine_terminal_placeholder`, and `NoRasterSourceProvided`, checked inside the strategy. Every other failure on the D8 path is fatal in both modes, which makes `BestEffort` and `RequireD8` differ only in whether a missing declaration is tolerated.

The 2026-07-24 live fire measured the cost of that shape. A reader capability gap, 0.2.0 bounding extent reads at 256 KiB against a 24.5 MiB tile index, surfaced as a selection error, and the fatal path turned it into a planet-wide carve outage for every default GRIT delineation while the manifest amendment was live. The failure was in the reader, not in the user's request, and the user had asked only for refinement if it were available.

`BestEffort` will therefore have no failing outcome. Every failure reachable on the D8 refinement path becomes a typed `BestEffortSkipped` reason carried on the result: selection failures, raster localization and open failures, unsupported declared CRS, tile dimension or geo-transform mismatch, a nodata sentinel that decodes as a legal direction, and any other malformed-input rejection introduced by this vision's ingestion checks. The delineation returns the unrefined terminal geometry. Hard failure on the same conditions remains available and unchanged under `RefinementMode::RequireD8`, which is the mode that means the caller needs the refinement.

The rejected alternative was an integrity contract: degrade on availability failures but stay fatal when the raster or its declaration lies, on the reasoning that a lying dataset is broken and continuing quietly misreports the problem. It is rejected because it reproduces the outage shape this vision exists to eliminate. Under a hosted planetary dataset, one bad metadata line in one declaration is not a local integrity event; it is every user's delineation failing at once, and the users affected can neither diagnose nor fix the declaration. A mis-declaration that degrades a planet to unrefined terminals is recoverable by publishing a corrected manifest. A mis-declaration that hard-fails a planet is an outage.

The rejected alternative's concern is answered in the skip reason rather than in the exit status. `BestEffortSkipReason` grows beyond its two availability variants to distinguish availability from mis-declaration and to carry the underlying typed error, so a degraded carve names which occurred. An operator reading provenance sees that the declaration lies; a user without a raster source sees that none was attached. A skip reason that says only "skipped" would make this decision a silent quality regression, so a non-diagnosable reason variant is not an acceptable implementation of it.

This narrows what `RefinementOutcome::Applied` promises and widens what `BestEffortSkipped` must explain, both of which are public behavior. It does not change `RequireD8`, and it does not make any currently-fatal condition unobservable.
